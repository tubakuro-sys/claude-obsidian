## 📋 やったこと（2026-07-08）

### Step 1：GitHub公開
- [x] `C:\自作ツール\apl\looppuzzle` をgit初期化、元HTML（Downloads内）を `index.html` として配置
- [x] `gh` CLI・`ffmpeg` を winget でインストール
- [x] `gh auth login`（ブラウザ経由・デバイスコード認証）でGitHubアカウント `tubakuro-sys` にログイン
- [x] `gh repo create loop-candy-puzzle --public --source=. --push` でリポジトリ作成＆初回push
- [x] GitHub Pages有効化（`main`ブランチ／ルート）、ビルド完了・200 OK確認

### Step 2：pushを楽にするバッチファイル
- [x] `push.bat` を作成（`git add -A` → コミットメッセージ入力 → `commit` → `push` を1クリックで実行）
  - 最初は日本語プロンプト＋`chcp 65001`で作ったが、バッチ内でのコードページ切り替えが原因で行が文字化け・誤動作 → **英語表記に変更して解決**（教訓：`.bat`に日本語を書く場合は`chcp`との組み合わせに注意）

### Step 3：広告動画が流れないバグ修正
- **原因**：コードが `ad.mp4` という固定ファイル名を探しに行っていたが、実際に置いていた動画ファイル名（`1000002571.mp4`など3つ）と一致せず、読み込みエラーで即スキップされていた
- **対応**：`AD_VIDEO_SOURCES` 配列に3ファイルを登録し、広告表示のたびにランダムで1本再生するよう修正

### Step 4：音声が流れない・動画がラグい問題の修正
- **音声**：`<video muted>` を外し、まず音声ありで自動再生を試行 → ブロックされたらミュート再生 → それでもダメなら手動再生ボタン、という3段フォールバックに変更
- **ラグの原因1**：広告動画が1920×1080・約14〜18Mbpsという非常に高ビットレート（スマホ録画そのまま）だった
  → `ffmpeg`で720p・2〜4Mbps程度に再エンコード（8〜11MB → 1.5〜2.6MBに軽量化）
- **ラグの原因2**：広告オーバーレイ（黒背景）の裏でCanvasの盤面描画ループが毎フレーム動き続けており、動画デコードとCPU/GPUを奪い合っていた
  → 広告再生中（`adPlaying`フラグ）はCanvas描画を完全停止し、終了後にシームレスに再開するよう修正
- ローカルで動作確認済み（音声あり自動再生・正常終了・描画停止を確認）→ コミット・push・Pages反映まで完了
