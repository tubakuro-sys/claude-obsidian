# 家族共有アプリ（Supabase版）実装・リリース手順書

CookGo参考のレシピ機能＋タスク機能を、Supabase（SQL）で。1プロジェクトに同居し、家族ごとにデータを仕切る。配信はGitHub Pages、形態はPWA。費用は無料枠内で¥0。

> ※ 旧Firebase版の手順書・計画書はこの版に置き換え。

---

## 帰宅後の最短ルート（迷ったらこの順）
1. Supabaseプロジェクト作成（手順1）
2. `schema.sql` を SQL Editor に貼って実行（手順2）
3. Google認証を有効化＋リダイレクトURL設定（手順3）
4. 家族を1組だけ作って自分の family_id を設定（手順7）
5. アプリ雛形を作って動作確認（手順4・5）
6. GitHub Pagesで公開＆家族に共有（手順6）
7. 停止対策のpingを設定（手順8）

> まずは「レシピ登録・共有・一覧・タグ検索」までを目標（フェーズ1）。献立/買い物リスト/AI取り込みは後回し。

## 0. 用意するもの
- メールアドレス（Supabase登録用。GitHubアカウントでもログイン可）
- Googleアカウント（家族のログイン用＝Google認証）
- アプリ用アイコン2枚：`icon-192.png` / `icon-512.png`
- 同梱の `schema.sql`

---

## 1. Supabaseプロジェクト作成・キー取得
1. https://supabase.com/ → サインイン →「New project」
2. 組織を作成し、プロジェクト名・データベースパスワード（控える）・リージョン（Tokyo推奨）を設定
3. 作成後、左メニュー「Project Settings」→「API」で次の2つを控える：
   - **Project URL**（`https://xxxx.supabase.co`）
   - **anon public key**（公開してよいキー。アプリに埋め込む）
4. ★ `service_role` キーは秘密。アプリやGitHubに**絶対に置かない**。

---

## 2. テーブル作成（schema.sql実行）
1. 左メニュー「SQL Editor」→「New query」
2. 同梱の `schema.sql` の中身を全部貼り付け →「Run」
3. エラーが出なければ、Table Editor にテーブル群（families, profiles, recipes …）が並ぶ
4. これでテーブル＋RLS（家族ごとの仕切り）＋プロフィール自動作成まで完了

---

## 3. Google認証の有効化＋リダイレクト設定
1. 左メニュー「Authentication」→「Providers」→「Google」を有効化
   - Google CloudでOAuthクライアントID/シークレットを取得して設定（画面の案内に従う）
2. 「Authentication」→「URL Configuration」で次を設定（★ここを忘れるとログイン後に戻れない）：
   - **Site URL**：公開予定のGitHub Pages URL（例 `https://ユーザー名.github.io/リポジトリ名/`）
   - **Redirect URLs**：同上を追加。ローカル確認用に `http://localhost:5500` 等も追加しておくと楽

---

### app.js
```javascript
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';

const SUPABASE_URL = 'ここに Project URL';
const ANON_KEY = 'ここに anon public key';
const supabase = createClient(SUPABASE_URL, ANON_KEY);

const signinBtn = document.getElementById('signin');
const signoutBtn = document.getElementById('signout');
const appMain = document.getElementById('app');
const addform = document.getElementById('addform');
const titleInput = document.getElementById('title');
const list = document.getElementById('list');

signinBtn.onclick = () =>
  supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: location.href } });
signoutBtn.onclick = () => supabase.auth.signOut();

supabase.auth.onAuthStateChange((_event, session) => {
  const loggedIn = !!session;
  signinBtn.hidden = loggedIn;
  signoutBtn.hidden = !loggedIn;
  appMain.hidden = !loggedIn;
  if (loggedIn) loadRecipes();
});

async function loadRecipes() {
  const { data, error } = await supabase
    .from('recipes')
    .select('id, title')
    .order('created_at', { ascending: false });
  if (error) { console.error(error); return; }
  list.innerHTML = '';
  data.forEach((r) => {
    const li = document.createElement('li');
    li.textContent = r.title;
    const del = document.createElement('button');
    del.textContent = '削除';
    del.onclick = async () => {
      await supabase.from('recipes').delete().eq('id', r.id);
      loadRecipes();
    };
    li.appendChild(del);
    list.appendChild(li);
  });
}

addform.onsubmit = async (e) => {
  e.preventDefault();
  const title = titleInput.value.trim();
  if (!title) return;
  // family_id はRLSのwith checkで本人の家族に限定。値はmy_family_id()で確認済の前提
  const { data: prof } = await supabase
    .from('profiles').select('family_id').single();
  await supabase.from('recipes').insert({ title, family_id: prof.family_id });
  titleInput.value = '';
  loadRecipes();
};
```

> リアルタイム同期が欲しくなったら `supabase.channel(...).on('postgres_changes', ...)` を後で追加。最初はボタンで再読み込みでも十分。

### service-worker.js
```javascript
const CACHE = 'family-app-v1';
const ASSETS = ['./', './index.html', './app.js', './style.css', './manifest.json'];
self.addEventListener('install', (e) =>
  e.waitUntil(caches.open(CACHE).then((c) => c.addAll(ASSETS))));
self.addEventListener('activate', (e) =>
  e.waitUntil(caches.keys().then((ks) =>
    Promise.all(ks.filter(k => k !== CACHE).map(k => caches.delete(k))))));
self.addEventListener('fetch', (e) => {
  if (e.request.url.includes('supabase') || e.request.url.includes('esm.sh')) return;
  e.respondWith(caches.match(e.request).then((r) => r || fetch(e.request)));
});
```

## 7. 家族メンバーの設定（family_id割り当て）
RLSは「自分の family_id と一致する行だけ」見せる仕組み。最初に紐付けが必要。
1. SQL Editor で `insert into families (name) values ('我が家');` を実行し、`select id from families;` でIDを控える
2. 各メンバーに一度Googleログインしてもらう（→ profiles に自動作成される）
3. Table Editor の `profiles` で、各メンバーの `family_id` に手順1のIDを設定
4. 妻側の家族を別グループにするなら、別の families 行を作り、そのメンバーの family_id をそちらに設定

> 将来「家族コードを入力して参加」のような仕組みにすれば手動設定は不要にできる（後フェーズ）。

## 8. 自動停止対策（GitHub Actionsで定期ping）
Supabase無料枠は7日アクセスがないと停止するので、数日おきに自動アクセスして起こし続ける。
1. リポジトリの Settings → Secrets に `SUPABASE_URL`、`SUPABASE_ANON_KEY` を登録
2. `.github/workflows/keepalive.yml` を作成：
```yaml
name: keepalive
on:
  schedule:
    - cron: '0 0 */3 * *'   # 3日ごと
  workflow_dispatch:
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -s "${{ secrets.SUPABASE_URL }}/rest/v1/families?select=id&limit=1" \
            -H "apikey: ${{ secrets.SUPABASE_ANON_KEY }}" \
            -H "Authorization: Bearer ${{ secrets.SUPABASE_ANON_KEY }}"
```
> リクエストが届くこと自体が「活動」とみなされ、停止を防げる。

## 12. つまずきやすい点
- **ログイン後に戻ってこない/エラー** → 手順3の Site URL・Redirect URLs 設定漏れ。GitHub Pages URLを登録。
- **データが0件しか出ない/権限エラー** → family_id 未割り当て、またはRLSポリシー。手順7を確認。
- **しばらくして重い/真っ白** → 自動停止。手順8のpingが動いているか確認（手動実行で起こせる）。
- **画面が更新されない** → service-worker.js の `CACHE` を v2,v3… に上げて再push。
- **キーの不安** → anon keyは公開前提でRLSが守る。service_role keyだけ厳重に秘匿。
