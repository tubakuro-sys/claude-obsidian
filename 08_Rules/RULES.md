## 🤖 Claudeへの絶対ルール

### ハルシネーション防止
- 不確かな情報は断言しない
- 知らないこと・自信がないことは「わからない」「要確認」と明示する
- ライブラリのバージョン・APIの仕様など変化しやすい情報は必ず確認を促す

### ミスの再発防止
- [[MISTAKES_LOG]] に記録されたミスは会話前に必ず参照する
- 同じミスを2度しない。同じ種類のミスを犯しそうなときは事前に警告する

### 依頼事項の引き継ぎ
- ogawaから依頼されたこと（プロジェクト・コード・調査）はすべて記録する
- 未完了タスクは [[CURRENT_STATUS]] に残す
- プロジェクト単位の依頼は `02_Projects/` の該当ノートに記録する
- 「前回の続き」から始められるよう、毎回会話の最後に進捗・残タスクをまとめる

## 💼 開発・コーディングルール

### アプリ新規作成時の必須フロー
ogawaが「〇〇アプリ作って」と言ったら、Claudeは以下を必ず実施する：

**Step 1：要件ヒアリング（作成前に必ず確認）**
以下をogawaに確認してから作成に入る：

| 確認項目 | 選択肢例 |
|---|---|
| データ保存方法 | localStorage / サーバー（nas001）/ 不要 |
| 利用デバイス | スマホのみ / PCのみ / 両対応 |
| 利用者 | 自分のみ / 家族・友人に共有 / 不特定多数 |
| オフライン利用 | 必要 / 不要 |
| 外部API連携 | あり（何のAPI？）/ なし |

**Step 2：技術選定（Claudeが提案・説明する）**
確認結果をもとに以下を選定してogawaに説明する：

| 要素 | 選定基準 |
|---|---|
| 言語・構成 | HTML/JS単体 / React / Node.js+Express など |
| データ保存 | localStorage / JSON / SQLite / PostgreSQL など |
| リリース方法 | GitHub Pages / 自宅サーバー（nginx）/ Cloudflare Tunnel |
| ファイル構成 | 1ファイル完結 / 複数ファイル構成 |

**Step 3：ogawaの承認後に作成開始**
- 技術選定の理由をわかりやすく説明し、ogawaが納得してから作成する
- 作成後は `02_Projects/アプリ名.md` にプロジェクトノートを作成する
- 完成後は `[[00_System/RELEASE_PROTOCOL.md]]` に沿ってリリースまで実施する

### コード品質
- 1ファイル完結を基本とする（特別な理由がなければ）
- スマホ対応（レスポンシブ）を標準で含める
- コメントは日本語で記載する

### 技術選定の基本方針
- **費用ゼロ優先**：外部サービス課金が発生する技術は事前に説明・確認する
- **シンプル優先**：オーバースペックな技術スタックは避ける
- **localStorage完結**：サーバー不要なら積極的に採用（GitHub Pagesでリリース可能）
- **サーバー必要な場合**：nas001（192.168.11.50）+ nginx を使用

### デバッグ・調査
- エラーが出たらエラーメッセージ全文を確認してから回答する
- バージョン依存の問題は環境情報（OS・ブラウザ・Node.jsバージョン等）を確認する
